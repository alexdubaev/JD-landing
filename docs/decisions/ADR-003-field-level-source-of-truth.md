# ADR-003: Владение данными на уровне типа и поля

## Статус

Accepted — 13 августа 2026 года.

## Контекст

Каталог Deere-Shop содержит 12 971 опубликованный товар. Карточка товара объединяет
данные разного происхождения и с разным жизненным циклом: коммерческие значения из
прайс-листов, вручную подготовленный редакционный текст, SEO, файлы, коды и связи.

Существующий импортёр строит полный payload и при совпадении SKU выполняет `PATCH`
существующего товара целиком. Такой подход не различает владельцев полей и способен
перезаписать вручную отредактированные название, URL, SEO, изображения и отношения.

Одновременно миграции галереи, редактора статей, кодов и аналогов требуют смены
источника истины по отдельным типам данных. Объявление одной системы владельцем всей
карточки товара создаёт лишнюю связанность и делает безопасный rollback практически
невозможным.

## Решение

Источник истины определяется не для товара целиком, а для каждого типа данных и
набора полей.

| Тип данных | Канонический владелец |
|---|---|
| Цена, статус цены, наличие, срок поставки и время обновления источника | Утверждённый профиль специализированного importer/reconciliation engine |
| Название, описания, категория, применимость, CTA и SEO | Редакторы в Directus |
| Основное изображение и галерея | `products.main_image`, `product_images` и Directus Files |
| Основной артикул производителя | `products.mpn` |
| Дополнительные OEM/MPN/supplier/previous/external/barcode-коды | `product_codes` |
| Аналоги, OEM cross, совместимость и supersession | `products_analogs` |
| Статьи и редакционное состояние | `articles`, Content Versioning и утверждённые relation collections |
| Публикация контента | Только Publisher/Admin |
| Массовые slug-, URL- и source-of-truth-миграции | Только Admin/Owner после отдельного release gate |

Каждый импорт-профиль обязан иметь явный allowlist. Поступившее запрещённое поле
помечается как conflict/rejected и не игнорируется молча. Изменяется только минимальный
patch реально отличающихся разрешённых полей; полный payload для существующего товара
запрещён.

Профиль по умолчанию может обновлять только уже существующие операционные поля:

- `price`;
- `price_status`;
- `availability_status`;
- `delivery_status`;
- `source_name`;
- `source_url`;
- `verified_at`.

Вес разрешается только отдельным opt-in профилем из доверенного источника. Название,
описания, категория, slug, SEO, изображения, применимость, аналоги, OEM-коды и вручную
редактируемый контент требуют отдельного opt-in профиля, preview полного diff и явного
подтверждения до apply.

Поля для нескольких цен, складов, предложений поставщиков и закупочной цены не
добавляются до появления утверждённого feed contract и доказанной модели данных.

Смена источника истины выполняется по одному типу данных через последовательность:

1. backup и baseline;
2. dependency audit;
3. additive target model;
4. dry-run и before-state artifact;
5. dual-read с fallback на старый источник;
6. reconciliation и route QA;
7. отдельное утверждение cutover;
8. наблюдение и возможность возврата;
9. вывод legacy-поля только отдельным релизом.

Автоматический worker или migration не вправе самостоятельно объявлять новый источник
истины. Content factory может создать только draft; массовый импорт не может повысить
статус до `published` по умолчанию.

## Следствия

- Очередной Excel/feed не может уничтожить вручную подготовленную карточку товара.
- Rollback ограничивается конкретным типом данных и не требует отката всей карточки.
- Frontend временно поддерживает dual-read во время каждой source-of-truth миграции.
- `products.mpn` сохраняется при введении `product_codes`.
- Legacy HTML статьи и legacy JSON товара не очищаются одновременно с включением новой
  модели.
- Roles/policies являются backend-контролем, но их изменение выполняется только
  отдельным security-scoped релизом.

## Рассмотренные альтернативы

### Importer владеет всей карточкой товара

Отклонено: полный feed не знает редакционного контекста и перезаписывает ручной
контент, SEO, связи и медиа.

### Directus владеет всеми данными, importer только создаёт новые записи

Отклонено: цены и остатки требуют регулярной автоматизированной синхронизации и
контроля свежести.

### Один JSON-документ как каноническая карточка

Отклонено: ухудшает целостность relations, индексирование, поиск, permissions,
reconciliation и работу штатной Directus Studio.
