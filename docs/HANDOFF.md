## Правило работы с Git и публикацией

Работать непосредственно в `main`. Перед коммитом и push обязательно получать состояние удалённой ветки:

```powershell
git fetch origin main
git log --oneline --left-right main...origin/main
```

Если в `origin/main` появился новый коммит, сохранить его и перенести собственный коммит поверх него через `git rebase origin/main`. Не использовать force-push. В рабочем дереве присутствуют сторонние временные файлы `.tmp-*` и `.tmp-parts-request/`; они не относятся к проектным изменениям и не должны добавляться в коммиты без отдельного решения владельца.

После push production обновляется только из `main`:

```bash
cd /opt/jd-landing/release
git pull --ff-only
cd deploy
sudo -n bash deploy.sh
```

Сборка может продолжаться на сервере после обрыва вывода SSH. В таком случае проверять результат, а не перезапускать её повторно:

```bash
cd /opt/jd-landing/release/deploy
sudo -n docker compose --env-file /opt/jd-landing/.env -f compose.production.yml ps
```

Никогда не выводить содержимое `/opt/jd-landing/.env`, токены Directus, SSH-ключи и `REVALIDATE_SECRET` в терминал, документацию или коммиты.

### Замены (аналоги)

В Directus у `products` создано JSON-поле `analog_skus` с русской подписью «Замены».

- Frontend получает его в `frontend/src/lib/directus/catalog.ts` и выводит после основного артикула в `frontend/src/components/catalog/ProductDetail.tsx`.
- В карточке товара замены показываются как `Замены: ART-1, ART-2`.
- 13 августа 2026 года обработан файл `deere_shop_only_with_analogs.csv`: **53 из 53** артикулов сопоставлены однозначно, их названия заменены значениями из столбца `Товар`, а значения `Аналоги` сохранены в `analog_skus`.
- Скрипт с обязательной предварительной сверкой: `scripts/apply-product-analogs.mjs`. Он требует `DIRECTUS_URL` и либо `DIRECTUS_TOKEN`, либо пару `DIRECTUS_ADMIN_EMAIL` / `DIRECTUS_ADMIN_PASSWORD`. Скрипт прекращает работу до изменения данных при отсутствии артикула или неоднозначном совпадении.

Пример проверки уже опубликованной позиции: `RE541925A` имеет название «Фильтр топливный RE541925A» и замену `PGF7949`.

## Удалённый служебный блок

На страницах товаров больше не выводятся служебные фразы вида:

- «Проверка данных»;
- «Данные проверены по сведениям, доступным для позиции …»;
- «Источник: Deere-shop».

Причина: это не содержимое CSV и не текстовые поля товара. Фразы формировались единым React-компонентом `ProductVerification` для всех позиций с заполненными служебными полями источника. Компонент и его тест удалены в коммите `adc4537`; ссылка на него удалена из `ProductDetail`.

Служебные поля `source_name`, `source_url`, `verified_at`, `reviewed_by` сохранены в Directus для внутреннего учёта, но фронтенд их больше не отображает. Перед удалением компонента просмотрены текстовые поля всех 12 971 товаров (`short_description`, `full_description`, `seo_text`, `seo_title`, `seo_description`, `image_alt`): таких фраз в самих данных не найдено.

Регрессионный тест в `frontend/src/app/catalog/[categorySlug]/[productSlug]/page.test.tsx` проверяет, что блок не появляется даже если у товара есть источник, дата проверки и проверяющий.

## Важные редакционные ограничения

- Не заявлять, что магазин является официальным представителем John Deere, если это отдельно не подтверждено владельцем.
- SEO-тексты должны объяснять назначение и выбор товара; не допускать переспама, служебных приписок, выдуманных характеристик, цен или наличия.
- Meta Keywords не используется: современным поисковым системам он не нужен. Поддерживать уникальные `title`, `description`, H1, ALT и полезный текст.
- Заглушка применяется к отсутствующим изображениям, но не является основанием повышать такие товары в каталоге выше старых карточек с реальными фотографиями.
