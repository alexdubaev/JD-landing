# tech_debt — бэклог выравнивания проекта

Составлен 2026-08-25 по результатам ультра-глубокого ревью (3 зоны: frontend-компоненты,
data/API-слой, инфраструктура/скрипты/доки) с персональной верификацией ключевых утверждений
и одним проходом критического ревью независимым агентом (все факт-претензии перепроверены по коду;
4 ошибочных утверждения исправлены, 4 недостающих угла добавлены: TD-19, S-11, S-12, лимит /media
в TD-03).

Каждый файл `TD-NN-*.md` — самодостаточная задача: симптом, доказательства (file:line),
минимально достаточное решение, TDD-план, подводные камни, allowed-files (под ADR-002),
верификация и анти-скоуп.

Принципы бэклога (в согласии с AGENTS.md / ADR-002):

- **Никакого оверинжиниринга**: потолок каждой правки описан в разделе «Не делаем».
- Одна задача = один ревьюнутый коммит = объявленный список файлов.
- Сомнительные/деструктивные шаги (untrack файлов, правки в deploy) — только после «да» владельца.
- Задачи на рефакторинг делаются по TDD: характеристический тест сначала.

## Stage-2 — задачи посложнее (отдельное обсуждение с владельцем)

Сознательно вынесены за периметр «минимально достаточного»: каждая меняет архитектуру,
требует решения о судьбе фичи или инфраструктурных решений. Обсуждаем после закрытия P1–P3.

| # | Тема | Почему сложно / что решить |
|---|---|---|
| S-1 | Серверный SKU-поиск вместо full-scan | `resolveNormalizedSkuIds` тянет всю таблицу продуктов (catalog.ts:600–615). Решение: `_contains` по нормализованной колонке или расширение `/deere-shop/search`. Требует правок на стороне Directus (индекс/endpoint) — зона read-only по ADR-002 |
| S-2 | Автоматический rollback деплоя | Сейчас откат = git checkout + полная пересборка (DEPLOY.md). Вариант: тег `:previous` у образа + `up` по нему при провале healthcheck. Правки deploy.sh — чувствительная зона |
| S-3 | Рантайм zod-валидация ответов Directus | Все Raw*-типы — доверенные касты (client.ts:67). Минимальный envelope-guard + схемы для money-полей. Цена: производительность фечей и сопровождение схем |
| S-4 | Focus trap в Modal | Esc/backdrop есть, табуляция уходит из диалога (фильтры каталога). Нужно решить: ручной trap или `inert` на корне |
| S-5 | Мультивалютные тоталы корзины | total суммирует `unitPrice` без учёта currency (context.tsx:194–197). Сейчас один RUB — молча сломается при появлении USD-цены |
| S-6 | Захардкоженные тексты → CMS | articles-метадата, инлайн-фолбэки каталога, тексты HomeSelection/HomeContactHub. Требует контент-решений владельца, не только кода |
| S-7 | Миграция legacy product-полей | `galleryIds/specifications/documentIds` дублируются новыми `images/specificationItems/...` (dual-read R7A без критерия завершения, catalog.ts:357–360). Нужен критерий «миграция завершена» + перенос потребителей |
| S-8 | Распределённый rate-limit | Текущий лимитер in-memory per-instance (rate-limit.ts) — при втором инстансе/реплике перестаёт работать. Решение: хранить в Directus/Redis или принять ограничение |
| S-9 | seo-worker: слияние конфигов + судьба CLI apply | Две конфиг-системы с пересекающимися env; CLI `--apply` ведёт в тупик (cli.mjs:127–134). Решать вместе с операционной моделью SEO-фабрики |
| S-10 | outputs/ и data/price — вынос из git | 1257 файлов импорт-артефактов и 52 бинарника прайслистов в git/LFS. Целевое состояние: объектное хранилище + ссылка. Решение владельца о хранении |
| S-11 | Уведомления о заказах | Лиды шлют письмо менеджеру (`notifyNewLead`), заказы — нет (в `api/orders/route.ts` нет ни одного notify-вызова). Решить владельцу: ожидается ли письмо/сообщение о заказе; если да — переиспользовать notifications-модуль |
| S-12 | Судьба CSP | Сейчас `Content-Security-Policy-Report-Only` + `report-uri` на несуществующий роут (после TD-07 останется Report-Only без отчётов) + `script-src 'unsafe-inline' 'unsafe-eval'`. Реального enforcement нет. Решить: включить enforcing-режим с чисткой unsafe-* (работа по вычищению инлайн-скриптов) либо убрать CSP-заголовок совсем как враньё |
