# TD-16 — Добить тестами data-слой: leads.ts, редиректы категорий, файлы, sitemap-функции

- **Приоритет:** P3 (модули покрыты неравномерно: 937-строчный catalog.test.ts и ноль тестов у ряда экспортов)
- **Усилие:** S–M (~0,5 дня, механические характеристические тесты)
- **Тип:** tests
- **Зависимости:** после TD-09 (тестируем уже разрезанные модули).

## Симптом и влияние

Хорошо покрыто: каталог (основное), leads-роут, revalidate, media, notifications, security.
Не покрыто вообще (grep тестов на момент составления):

1. **`lib/directus/leads.ts`** — `safeAttachmentName` (`:11–20`, санитизация имён загружаемых файлов —
   security-смежная логика) и best-effort PATCH перемещения файла в папку (`:34–48`, обход
   известного бага Directus 12 с multipart `folder`).
2. **`getCategoryRedirect`** (`catalog.ts:819–836`) — управляет `permanentRedirect` со страницы
   категории (пользователь попадает на новый URL навсегда — 301; ошибка = сломанный SEO-цикл).
3. **`getFilesByIds`** (`catalog.ts:922–941`) — рендер документов продукта (скачивания).
4. **`getProductSitemapEntries`/`getCategorySitemapEntries`** (`catalog.ts:943–987`) — SEO-поверхность;
   фильтрация `isIndexable` и lastmod-логика без тестов.
5. **`filter_count` fallback** (`catalog.ts:792`) — ветка деградации подсчёта товаров.
6. **`lib/directus/env.ts`**, **`lib/seo/url.ts`** — мелкие, но с edge-поведением (fallback origin
   `https://deere-shop.ru` при пустом env — canonical'ы молча едут на прод-домен).

## Решение (минимальное)

Характеристические тести по образцу существующих (мок `directusRequest`/fetch):

- `leads.test.ts`: санитизация имён (`../../../etc/passwd` → базовое имя, расширение сохраняется,
  длина кэпится), PATCH-фолбэк при отказе — не роняет создание лида.
- `catalog.test.ts` (или модульные файлы после TD-09): редирект-объект при наличии записи и null при
  отсутствии; файлы — happy path + пустой набор; sitemap-entries — фильтрация неиндексируемых,
  lastmod из updated_at; filter_count fallback.
- `env.test.ts`: валидная/невалидная конфигурация (после TD-13 — с reset-хелпером).
- `url.test.ts`: абсолютизация, fallback-origin, слэши.

## Подводные камни

1. Это характеристические тести «как работает сейчас» — не переизобретать ожидания; если тест
   вскрывает баг (например, редирект на несуществующий slug) — фиксить отдельным коммитом с
   пометкой, не молча подгоняя ассерт.
2. Не гнаться за 100%: перечисленные функции — весь список; строки мапперов, покрытые транзитом,
   отдельно не тестируем.
3. Sitemap-функции завязаны на пагинацию `limit: -1`? — тестировать с моком, не поднимая Directus.

## Allowed files (ADR-002)

- только новые/расширенные `*.test.ts` рядом с перечисленными модулями (`frontend/src/lib/**`).

## Верификация

1. `npm test` — зелёные; покрытие перечисленных экспортов подтверждается grep'ом их имён в тестах.

## Не делаем
