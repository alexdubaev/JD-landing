# TD-14 — Аналоги/замены (R8): фича написана и протестирована, но не подключена

- **Приоритет:** P2 (полностью готовый код не работает в проде; тесты тестируют то, чего пользователь не видит)
- **Усилие:** S на подключение (~2–4 ч) или S на вынос (~1 ч)
- **Тип:** feature-wiring или deletion — **решение владельца**
- **Зависимости:** после TD-07 (если решим выносить — там же удалить).

## Симптом и влияние

Для карточек товара построен весь контур «аналоги/замены» (R8):

- `lib/directus/catalog.ts:433–537` — `fetchProductAnalogs(productId)` + маппинг в
  `ProductAnalogsView` (симметричные аналоги + superseded-by цепочки);
- `components/catalog/RelatedProducts.tsx:26+` — проп `analogs?: ProductAnalogsView` с группировкой
  и UI-рендером (~40 строк логики);
- `RelatedProducts.test.tsx` — 4 из 5 тестов покрывают именно аналоги.

Но страница продукта (`app/catalog/[categorySlug]/[productSlug]/page.tsx:145`) зовёт
`<RelatedProducts products={relatedProducts} />` **без** `analogs`, и `fetchProductAnalogs`
не вызывается ни в одном роуте/компоненте (grep: единственное упоминание — определение и тесты).

Итог: пользователь не видит блок аналогов; поддержка «замена устаревшей детали» — заявленная
ценность каталога запчастей (в данных есть replacement SKU — коммит `8410907 "Add product
replacement SKUs"`) — не доезжает до UI. Тесты дают ложную уверенность.

## Решение — две опции

### Опция A (рекомендуем): подключить
1. В `page.tsx` продукта добавить `fetchProductAnalogs(product.id)` в существующий
   `Promise.allSettled`-блок параллельных фечей (`:85–90`).
2. Прокинуть `analogs` в `<RelatedProducts>` (проп уже готов; UI уже написан).
3. Отказ феча (settlement rejected) → блок аналогов скрыт, остальная страница жива (тот же паттерн,
   что у остальных фечей страницы).
4. Тест страницы: мок `fetchProductAnalogs` → блок с аналогами рендерится; rejected → не рендерится.
5. Кэш-теги: аналоги читают те же продукты — наследуют теги `"products"` (уточнить в реализации
   `fetchProductAnalogs`, какие теги она ставит; если нет — добавить `"products"`, чтобы вебхук из
   TD-06 их освежал).

### Опция B: похоронить до лучших времён
Удалить `analogs`-ветку из RelatedProducts (+ 4 теста) и `fetchProductAnalogs` из lib (сначала
проверив, не нужен ли маппинг данным replacement SKU где-то ещё). Data-слой Directus не трогаем.

**Критерий выбора:** если бизнес планирует показывать «чем заменить снятую с производства деталь»
в ближайшие месяцы — A (код уже написан, стоимость подключения минимальна). Если фича заморожена
на неопределённый срок — B (мёртвый код с зелёными тестами хуже отсутствия кода), с лёгким
восстановлением из git-истории.

## Подводные камни (опция A)

1. **Права Frontend API role на `products_analogs`** — dual-read может требовать отдельной
   пермиссии (по аналогии с R7A, где child-rows читаются отдельным запросом из-за прав). Проверить
   на dev-инстансе, что феч не 403-ит; если нужно — правка прав роли (зона Directus, отдельное
   согласование по ADR-002!).
2. Пустой `ProductAnalogsView` (нет аналогов у товара) → блок не рендерить (не показывать пустую
   секцию «Аналоги»).
3. Не добавлять отдельный loading-скелет под блок — он рендерится в составе страницы (ISR).
4. **не** строить UI «цепочки замен» глубже существующего (superseded-by один уровень — как есть).

## Allowed files (ADR-002)

- Опция A: `frontend/src/app/catalog/[categorySlug]/[productSlug]/page.tsx` (+тест),
  при необходимости теги в `lib/directus/catalog.ts` (строки `fetchProductAnalogs`).
- Опция B: `frontend/src/components/catalog/RelatedProducts.tsx` (+тест),
  `frontend/src/lib/directus/catalog.ts` (удаление функции + её блок в catalog.test.ts).

## Верификация

- A: на dev-инстансе карточка товара с заведёнными аналогами показывает блок; без аналогов — не
  показывает; `npm test`.
- B: grep `fetchProductAnalogs|ProductAnalogsView` — пусто; тесты зелёные.

## Не делаем

- Не трогаем схему `products_analogs` и данные replacement SKU; не делаем админ-UI аналогов.
